## Задача

Система саппорта(Тикет система) с аналитикой и чатом для пользователей. Система является мультитенант системой. Будет дашборд с задачами. Через чат пользователи могут создавать задачи и добавлять информацию.

### Функциональные требования

**Три функциональных требования проистекают из условия:**
1. Нужно создавать задачи
2. Нужно Получать задачи списком
3. Нужно получать конкретную задачу

**Вопросы которые я бы задал интервьюеру:**
1. Из чего состоит тикет который необходимо создать, Он может содержать приложенные файлы? - Да, может.
2. Нужно ли рассылать уведомления, события при изменении статуса задачи, или просто при редактировании задачи? - Да, нужно уведомлять пользователя и исполнителя.
3. Могут ли задачи ссылаться друг на друга? - Нет
4. Жизненный цикл тикета, какие статусы? - ОТКРЫТ и ЗАКРЫТ
5. Какие фильтры для дашборда? - Для дашборда должна быть возможность пофильтровать по статусам,\
сортировать по исполнителям закрывшим больше всего задач.
6. Параллельное изменение тикета, что делать с этим? - тот кто не успел сохранить свои изменения получает сообщение о конфликте.
7. Должен ли тикет содержать историю изменений? - Да, Тикет содержит историю сообщений, изменений в тексте и изменение исполнителей.
8. Может задача переназначаться между людьми? - Да, изменение исполнителя должно отобразиться в истории изменений.
9. Чат реал тайм? - Да 
10. Комментарии в тикете это переписка в чате, или другое? - Нет, это отдельные данные для хранения.
11. Может ли в чате быть несколько человек одновременно? - Нет, чат индивидуальный и нужен только для создания задачи.
12. Если Получатель/Исполнитель в чате офлайн, что делаем, храним на сервере? - Да
13. В чат файлы можно отправлять? - Да.
14. Уведомления нужны на сообщение в чате для получателя или отправителя? - Да
15. Можно ли взаимодействовать с чатом с не скольких устройств? - Да
16. Как назначаются задачи на исполнителя? - Автоматически на свободного
17. Что есть тенант с точки зрения бизнеса, как пользователь туда попадает? - Принадлежность пользователя к организации определяет его принадлежность к тенанту.
