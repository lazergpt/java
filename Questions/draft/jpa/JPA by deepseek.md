# Вопросы по Spring Data JPA и Hibernate на собеседовании Senior Java Developer

> Выборка на основе открытых источников: отзывы и планы подготовки к Т-Банку, а также вопросы Senior-уровня из других компаний.  
> Формат: вопрос — краткое пояснение.

## Вопросы, которые чаще всего связывают с Т-Банком

1. **Как Hibernate управляет транзакциями и как это интегрируется с `@Transactional` Spring?**  
   Spring использует `JpaTransactionManager`; `@Transactional` через AOP-прокси открывает/коммитит/откатывает транзакцию Hibernate. Благодаря dirty checking явный `save()` не нужен — изменения сбрасываются при коммите.

2. **Что такое lazy loading и когда возникает `LazyInitializationException`?**  
   Загрузка связей откладывается до обращения к ним. Исключение возникает, когда сессия уже закрыта, а прокси пытается выполнить SQL для загрузки данных.

3. **Почему `spring.jpa.hibernate.ddl-auto=update` опасно использовать в продакшене?**  
   Hibernate не гарантирует корректную миграцию схемы: возможны неожиданные изменения, отсутствие контроля версий схемы и конфликты при параллельных деплоях. В продакшене обычно используют Flyway/Liquibase.

4. **Что такое проблема N+1 и как её решить?**  
   При загрузке N сущностей и последующем обращении к LAZY-связи выполняется N дополнительных запросов. Решения: `JOIN FETCH` в JPQL, `@EntityGraph`, `@BatchSize` или настройка `hibernate.default_batch_fetch_size`.

5. **В чём разница между кэшем первого и второго уровня?**  
   L1-кэш живёт в рамках `EntityManager`/сессии и включён всегда. L2-кэш живёт на уровне `SessionFactory`, требует провайдера (Ehcache, Redis и т.п.) и явной настройки.

6. **Как исправить `detached entity passed to persist`?**  
   Ошибка возникает при вызове `persist()` для сущности, у которой уже есть ID. Для отсоединённой сущности нужен `merge()`, который возвращает управляемую копию.

7. **Какие правила генерации идентификаторов настраивались в Hibernate?**  
   Вопрос проверяет понимание `IDENTITY`, `SEQUENCE`, `TABLE`, `AUTO` и их влияния на производительность (особенно отключение батчинга при `IDENTITY`).

8. **Система marketplace замедлилась под нагрузкой. Подозреваем проблему в БД. Что будем искать?**  
   Сценарный вопрос: план запросов, индексы, N+1, отсутствие батчинга, размер выборок, кэширование, блокировки.

## Сильные вопросы из других компаний (Senior-уровень)

9. **Четыре состояния жизненного цикла сущности JPA и переходы между ними.**  
   Transient → Persistent → Detached → Removed. Ключевые ловушки: `persist()` на detached бросает исключение; `merge()` возвращает новую управляемую копию, а не делает исходный объект управляемым.

10. **Чем `EntityManager.find()` отличается от `Session.load()`/`getReference()`?**  
    `find()` сразу идёт в БД и возвращает `null`, если записи нет. `load()` возвращает прокси без запроса; исключение возникает только при обращении к полям, если записи нет.

11. **Почему стратегия `IDENTITY` отключает JDBC-батчинг вставок?**  
    Hibernate не может заранее назначить ID, поэтому вынужден выполнять каждый INSERT отдельно и вызывать `getGeneratedKeys()`. `SEQUENCE` с `allocationSize` позволяет резервировать блок ID и батчить вставки.

12. **`Page` vs `Slice` в Spring Data JPA.**  
    `Page` выполняет дополнительный `COUNT(*)` для общего числа элементов. `Slice` только проверяет наличие следующей страницы (`hasNext()`), поэтому быстрее на больших таблицах.

13. **Оптимистичная vs пессимистичная блокировка.**  
    Оптимистичная (`@Version`) не блокирует строку, но проверяет версию при обновлении и бросает `OptimisticLockException`. Пессимистичная (`LockModeType.PESSIMISTIC_WRITE`) держит блокировку БД до конца транзакции — подходит для высококонкурентных операций (списание баланса, бронирование).

14. **Зачем нужны projections и когда они дают выигрыш?**  
    Позволяют выбирать только нужные поля вместо целой сущности: меньше данных, меньше нагрузка на persistence context, быстрее запросы для read-only сценариев.

15. **Как отладить медленное JPA-приложение в продакшене?**  
    Включать `hibernate.show_sql`/`format_sql`, статистику, `p6spy`/`datasource-proxy`, анализ планов запросов, поиск N+1 и лишних eager-загрузок, проверка батчинга и размера пачки.
