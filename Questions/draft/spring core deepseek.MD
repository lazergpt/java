## 🎯 Вопросы, специфичные для Т-Банка

- **Разбор кода с багами (Spring + Concurrency)**
  Кандидату дают фрагмент кода на ревью и просят найти в нем ошибки за ограниченное время. В одном из разборов нашли 8+ багов, связанных с `HashMap` в многопоточной среде, использованием `double` для денег, отсутствием валидации входных данных (`Map<String, Object>`), слишком широкой транзакцией с внешними вызовами и self-invocation, который «ломает» `@Transactional`.

- **Как понять, что проблема в сервисе связана с Spring Framework, а не с базой, сетью или бизнес-логикой?**
  Вопрос проверяет не заученные факты, а системное мышление и умение диагностировать проблемы в распределенной среде.

- **Какие поведения propagation транзакций существуют в Spring?**
  Классический вопрос на понимание того, как управлять транзакциями при вызове одного сервисного метода из другого (например, `REQUIRED`, `REQUIRES_NEW`, `NESTED`).

- **В каких backend-проектах Spring Boot является сильным выбором, а где лучше выбрать более простой или другой стек?**
  Senior-вопрос на понимание trade-off'ов и границ применимости технологии, а не просто на знание API.

## 🧠 Ядро Spring (IoC, DI, Beans)

- **IoC vs DI — в чем разница?**
  IoC (Inversion of Control) — это принцип, при котором управление созданием объектов передается контейнеру. DI (Dependency Injection) — это конкретный механизм реализации этого принципа, когда зависимости внедряются извне.

- **В чем разница между `BeanFactory` и `ApplicationContext`?**
  `BeanFactory` — это базовый, ленивый контейнер с минимальной функциональностью. `ApplicationContext` — его расширение, которое сразу инициализирует singleton-бины и поддерживает AOP, события, интернационализацию. В продакшене всегда используется `ApplicationContext`.

- **Почему внедрение через конструктор предпочтительнее, чем через поле (`@Autowired`)?**
  Конструктор позволяет сделать поля `final` (иммутабельность), явно обозначает зависимости, гарантирует, что объект не будет создан в невалидном состоянии (fail-fast при старте), и упрощает unit-тестирование без использования рефлексии.

- **Как Spring разрешает циклические зависимости?**
  Для singleton-бинов Spring использует «трехуровневый кеш»: он позволяет «подставить» частично инициализированный бин (early reference) в другой бин, чтобы разорвать цикл. Этот механизм **не работает** при внедрении через конструктор, что приводит к исключению `BeanCurrentlyInCreationException`.

- **Как разрешается зависимость, если есть несколько бинов одного типа?**
  Spring следует порядку: поиск по типу → аннотация `@Primary` → совпадение по имени бина или `@Qualifier`. Если однозначно определить не удается, выбрасывается исключение `NoUniqueBeanDefinitionException`.

## 🔄 Жизненный цикл бинов и прокси

- **Опишите жизненный цикл бина в Spring.**
  Основные этапы: инстанцирование (вызов конструктора) → заполнение свойств (DI) → вызов `*Aware` интерфейсов → `BeanPostProcessor.postProcessBeforeInitialization()` → методы инициализации (`@PostConstruct`, `afterPropertiesSet`) → `BeanPostProcessor.postProcessAfterInitialization()` (здесь создаются AOP-прокси) → бин готов → методы уничтожения (`@PreDestroy`).

- **В чем разница между `BeanPostProcessor` и `BeanFactoryPostProcessor`?**
  `BeanFactoryPostProcessor` выполняется раньше, до создания бинов, и может модифицировать метаданные определений бинов (например, заменять плейсхолдеры). `BeanPostProcessor` работает с уже созданными экземплярами бинов и может их оборачивать (например, создавать AOP-прокси).

## 💰 Транзакции

- **Как работает `@Transactional` под капотом?**
  Spring создает прокси вокруг бина. При вызове метода прокси перехватывает вызов, открывает транзакцию через `PlatformTransactionManager`, выполняет метод и затем делает `commit` или `rollback` в зависимости от того, было ли выброшено исключение (по умолчанию, только `RuntimeException`).

- **В чем проблема self-invocation (вызова метода через `this`) при работе с `@Transactional`?**
  Поскольку Spring использует прокси, вызов метода через `this` не проходит через прокси-объект. Следовательно, логика управления транзакцией (открытие/закрытие) не применяется. Чтобы избежать этого, нужно либо вынести метод в другой бин, либо использовать `AopContext.currentProxy()`.

## 🚀 Spring Boot

- **Как работает авто-конфигурация в Spring Boot?**
  Spring Boot сканирует classpath, находит в `META-INF/spring.factories` (или `.imports`) классы авто-конфигурации, аннотированные `@Configuration`. Они активируются условно, в зависимости от наличия определенных классов, бинов или свойств (`@ConditionalOnClass`, `@ConditionalOnMissingBean` и т.д.).
