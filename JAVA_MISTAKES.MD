1. Числовые объектные переменные в условных выражениях

Ожидается, что пример ниже вернёт `null`, для `value = null;` 
```java
Double valueOrZero(boolean condition, Double value)
{
    return condition ? value : 0.0;
}
```
Но на уровне байткода выражение преобразуется в 

```java
Double valueOrZero(boolean condition, Double value)
{
    return Double.valueOf(condition ? value.doubleValue() : 0.0);
}
```
что вызовет `NPE`.
2. Передача `null` в метод с переменным количеством аргументов

```java
// Я хочу, чтобы массив содержал пустое значение
printAll((Object)null);
// Я хочу, чтобы массив являлся пустой ссылкой
printAll((Object[])null);
```
3. Связь ссылки на метод с неверным методом
В примере ниже ожидается вызов дефолтного пустого конструктора
```java
contents.computeIfAbsent(fileName, StringBuilder::new);
```
Но вызывается конструктор принимающий один параметр, являющийся в нашем случае ключём Map и он тут нам нафиг не нужен.
```java
contents.computeIfAbsent(fileName, s -> new StringBuilder(s));
```
4. Взаимоблокировка при инициализации класса

#### Ситуация с двумя классами, в которых статические поля инициализируются новыми экземплярами дург друга.
Поскольку виртуальная машина гарантирует, что инициализатор класса не выполняется дважды, он блокируется во время инициализации класса.
Когда один класс инициализируется во время инициализации другого, устанавливаются две блокировки.
Если еще один поток пытается запросить те же две блокировки в обратном порядке, происходит взаимоблокировка.
#### Ситуация с двумя классами, в которых статические поля инициализируются новыми экземплярами дург друга.
Похожая ситуация происходит когда суперкласс объявляет поле типа подкласса, взаимоблокировка вполне возможна, если один поток запустит инициализацию класса А, а другой — инициализацию класса В
```java
class A {
    public static final A INSTANCE = new B();
}
class B extends A {
}
```
